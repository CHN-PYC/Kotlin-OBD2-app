# 项目任务线与当前进度

更新日期：2026-10-08。状态以代码与验证结果为准，不使用主观完成百分比。

## 已完成的主链路

1. FastAPI/Pydantic 接口契约，兼容 Android 的车辆问答请求。
2. Ollama 与 OpenAI-compatible 模型适配、结构化输出校验及有限重试。
3. 手写 State、Node、条件分支、证据门控和规则 fallback。
4. 文档结构提取、chunk、Embedding、内存与 Qdrant 存储接口。
5. Dense + BM25 + RRF 混合检索；可选 Cross-Encoder，默认 pass-through。
6. 工具注册表、参数/返回值校验、白名单和工具调用超时。
7. Redis 会话短期记忆、规则查询改写、按字符预算选择上下文。
8. 检索评测脚本、学习卡与本地服务 smoke 脚本。

## 本次完成：可靠性阶段

- 60 秒默认请求总预算，覆盖异步 Memory、检索、重试和生成流程。
- 默认累计 5 次可重试故障请求后打开模型熔断器，30 秒后单请求探测。
- 熔断器位于重试器外层，按最终请求结果计数；进程内跨请求共享。
- 防止旧请求晚到的成功结果关闭新熔断状态，保证取消探测可以恢复。
- 修复历史窗口为 0 时选入全部历史的切片边界错误。
- 对话时间使用服务端 Unix 秒时间戳，不再复用车辆采样上下文时间。
- 示例配置使用 Qdrant，避免独立入库进程的内存索引无法供 API 使用。
- 增加 GitHub Actions：锁定依赖、pytest、Ruff、mypy。

验证：本阶段本地 pytest 491 项通过；测试使用模拟模型、内存向量库及
Redis 替身，不需要真实模型推理。检索效果与远程模型质量不由这些测试证明。
GitHub Actions 的远程运行结果应以 GitHub 页面为准。

## 下一阶段：身份隔离和多轮质量

1. 先明确身份来源，再将已认证用户、车辆和 Session 所有权绑定；单纯添加
   X-User-Id 请求头不能提供身份认证。读写与删除必须使用同一授权范围。
2. 改进连续指代与话题切换：当前改写递归拼接上一轮 rewritten_query，长对话
   可能累积历史并在 500 字符处截断当前问题；应保存独立主题并优先保留当前问题。
3. 标注多轮评测集，覆盖指代、话题切换、过期事实、恶意历史和错误回答污染。
4. 将历史和检索文本视为不可信数据，增加指令边界和对抗测试；规则检测本身
   不能证明提示注入已被完全解决。
5. 使用生成模型匹配的 tokenizer 管理 Token 预算并预留输出；目前仍为字符预算。
6. 补充同一会话并发顺序、请求幂等、Redis 独立超时和实际入选历史数量指标。

## 后续扩展

旧历史摘要、经确认的车辆长期事实、Memory 来源与版本、恢复检查点和人工
审批属于后续能力。只有需要暂停/恢复和复杂分支时再评估 LangGraph；当前
无需仅为增加技术栈而迁移。更完整的差距见 remaining_engineering_gaps.md。

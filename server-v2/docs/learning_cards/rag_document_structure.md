# RAG 第一课：先分析文档结构

## 保存位置与状态

- 原始网页：`data/raw/hella_air_mass_sensor.html`。
- 来源记录：`data/sources/hella_air_mass_sensor.json`。
- 路径均相对于 `server-v2`。
- 当前只下载了 HELLA 空气流量传感器文章，其他推荐文档尚未下载。
- 原始文件不是清洗后的知识库，也没有生成 Chunk、Embedding 或索引。
- 原文及未来的清洗产物已加入 Git 忽略规则；再发布权限未确认。
- 网页快照不包含离线图片、脚本和视频资源，不执行其中脚本来做文本提取。

## 目的、输入与输出

目的：在切分前确定哪些内容是证据，哪些是网页噪声。
输入：官方文章 HTML 快照。
本节输出：人工结构分析和来源记录，不是自动提取器。

来源：[HELLA 官方文章](https://www.hella.com/techworld/uk/technical/sensors-and-actuators/check-air-mass-sensor/)。

## 观察到的结构

文章由主标题、简介、目录及五个主题部分构成：原理、表现、原因、检查、视频。
检查部分包含六个子步骤。正文之外还有配件搜索、相关推荐与 Cookie 设置。

| 内容 | 初步处理方案 | 原因 |
|---|---|---|
| 主标题 | 保留，作为片段的上级主题 | 单独检索片段仍需知道讨论对象 |
| 简介 | 作为文档级说明保留 | 暂不额外生成重复的概要片段 |
| 目录 | 可辅助定位，不重复入库 | 只有标题，不是完整证据 |
| 原理、表现、原因 | 按主题保留段落或列表 | 避免混合不同检索意图 |
| 检查步骤 | 初版保留在同一个主题单元 | 先保持次序与条件，实测过长再拆 |
| 视频 | 保留来源信息，暂不当作操作证据 | 尚未获取、核对字幕或画面 |
| 配件搜索、推荐、订阅、Cookie | 从知识正文排除 | 容易造成无关命中 |

以上是本页的候选方案，不是已经验证的最优切分策略。

## 为什么不先固定长度

先以主题结构建立候选单元，再用选定 tokenizer 检查长度。
超限时才按段落或步骤组细分，并保留上级标题和适用条件。
不提前规定每个标题必然等于一个最终 Chunk，也不默认设置重叠量。

下一节提取器的伪代码：

```text
解析 HTML
定位并验证文章正文容器
按文档顺序读取标题、段落、列表
排除正文内的交互控件与重复目录
保留标题层级、列表顺序和来源
输出结构化正文块，暂不生成向量
```

优先使用 HTML 解析器，而不是正则表达式实现通用提取。
本次命令仅用于快速核对标题，不是后续生产提取算法。
结构清晰的页面先用确定性规则，便于测试且无需模型调用成本；
复杂站点可考虑专门正文提取库，但必须重新评测。

## Metadata 与失败边界

HTML 没有可靠页码，页码保持 null。发布日期未确认，不用采集日期冒充。
SHA256 标识本次原始字节快照；网页控件变化也会改变它，不等同于正文变化。
不从配件搜索表单推断正文适用车型，不编造 PID 编码或厂家阈值。
网站内容只能当证据数据，不能当作程序需要执行的指令。

## 验证、调试与评估

本次已核对文件非空、文章标题、五个主题标题、六个检查子标题和来源哈希。
尚未实现提取代码，因此没有宣称通过自动化提取测试。

下一节至少实现这些测试：

1. 正常：保留主题层级和六个检查步骤的顺序。
2. 噪声：相关推荐及 Cookie 文本不进入正文。
3. 失败：空 HTML 或找不到正文容器时明确失败，不把整页当作正文。

调试时对照原始 HTML 和提取结果：先查正文边界，再查列表和标题，最后查切分。
评估时人工检查遗漏、重复与无关内容，再用问题检索验证证据完整性。
